# ADR-005: Tech Stack Used

## Status
**Status:** Approved

## Context and Problem Statement
The Advanced Media Library application requires a robust, scalable, and modern tech stack capable of handling a dynamic user interface and complex media operations. The selected stack must meet the requirements for high performance, maintainability, and a seamless user experience. This decision aims to standardize the tools and technologies to be used during development.

## Decision Drivers
The decision drivers for choosing the tech stack are:
- **Driver 1**: Need for a high-performance backend to manage advanced media processing and database operations.
- **Driver 2**: A dynamic and responsive front-end framework to deliver a rich user experience.
- **Driver 3**: Ease of integration between frontend and backend components.
- **Driver 4**: Established ecosystem and community support for better troubleshooting and scalability.
- **Driver 5**: Alignment with the team's existing expertise to ensure efficient development, as Liam has prior experience using Express, whilst Guy has experience with Flask.

## Options Considered
- **Option 1**: Node.js with Express.js for the backend, React for the frontend.
- **Option 2**: Python with Django for the backend, React for the frontend.
- **Option 3**: Ruby on Rails for the backend, Angular for the frontend.
- **Option 4**: PHP with Laravel for the backend, Vue.js for the frontend.

## Decision Outcome
- **Decision**: The team will adopt **Node.js with Express.js** for the backend and **React** for the frontend.
- **Rationale**: 
  - Node.js and Express.js offer excellent performance and scalability for real-time and asynchronous applications.
  - React ensures a component-based architecture, making it easier to build and maintain a highly interactive and responsive user interface.
  - The combination provides seamless integration through RESTful APIs and simplifies communication between front and backend.
  - The team has significant experience in these technologies, reducing ramp-up time.

## Consequences
- **Positive Outcomes**:
  - Scalable architecture for handling media operations.
  - Enhanced performance due to non-blocking I/O and virtual DOM.
  - Large community support and rich libraries/plugins availability.
- **Negative Outcomes**:
  - Potential challenges in server-side rendering for React (can be mitigated with Next.js in the future).
  - Increased reliance on JavaScript across the stack could be a learning curve for team members unfamiliar with full-stack JavaScript such as Lewis and Guy.

### Mitigation Strategy
- Leverage best practices and frameworks (e.g., middleware in Express.js).
- Provide training materials in sprint planning for team members to upskill in selected technologies, in addition to peer help and use of components that can be replicated and understood amongst the team.

## Confirmation
- Periodic reviews of the tech stack during the project milestones to ensure it continues to meet performance and development goals.
- Conduct performance benchmarking and load testing to validate system efficiency.

## Pros and Cons

### Pros
- High performance and scalability with non-blocking architecture.
- Easy integration between React frontend and Express.js backend.
- Extensive documentation, community support, and ecosystem.

### Cons
- Server-side rendering might require additional tools.
- Potential complexity in managing asynchronous code.
